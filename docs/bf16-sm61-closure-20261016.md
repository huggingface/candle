# BF16 matmul on pre-Ampere CUDA — closure audit

Base: `bf16_candle` at `8a7c2aa3ae70e195f96f662f9a9038a3d43fa56d`.

## Behavior

With `cuda-legacy-bf16`, BF16 matmul on compute capability below 8.0 now
materializes the logical operands as FP32, calls cuBLAS SGEMM, and rounds the
result to BF16 once. This preserves BF16's exponent range. It does not pass
`CUDA_R_16BF` to a pre-Ampere GEMM or convert the operands through FP16.

Offsets, transposes and broadcast strides are applied while materializing the
operands. The native BF16 path on Ampere and newer remains available. The
ordinary FP32 GEMM implementation is unchanged. The software path owns two
temporary FP32 operands and a temporary FP32 output; allocation failures remain
explicit errors. There is no persistent converted-weight cache.

Regression cases cover nonzero offsets, transposed operands, batched broadcast,
the output dtype, and exact powers of two outside FP16's exponent range.

The branch also preserves its existing examples forwarding alias and migrates
the yanked ZIP dependency to `=9.0.3`, including the fallible/Cow filename APIs
used by NPZ and PyTorch checkpoint readers.
